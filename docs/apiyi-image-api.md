# APIYi 图片编辑并发和失败处理

核对日期：2026-08-29。

本页记录批量图片编辑 worker 必须遵守的外部接口事实。来源：

- [图片 API 调用须知与最佳实践](https://docs.apiyi.com/api-capabilities/image-api-best-practices)
- [API 可以开多少并发？](https://docs.apiyi.com/faq/api-concurrency)

## 已确认的接口行为

- 图片接口是同步调用：客户端保持同一个 HTTP 连接，图片直接随响应返回。
- 平台不提供异步任务 ID、轮询接口或断线后找回图片的能力。这里的“任务队列”只能由 InsertAny3D
  在本地自己维护，不能写成 APIYi 的服务端队列。
- 客户端超时或连接断开后，上游仍可能继续生成并计费；这种情况必须记为 `delivery_unknown`，不能自动
  当作一次免费失败重新发送。
- 图片模型公开默认额度是每个令牌、每个具体模型 30 个并发。不同令牌、不同模型分别计算；实际令牌可能
  被单独调整，因此运行时以控制台和响应头证据为准，不能把 30 硬编码成真实额度。
- 超过并发或上游额度时返回 HTTP `429 Too Many Requests`，不是静默排队。`429` 和 `503` 可以按
  `5/15/45` 秒指数退避；响应带 `Retry-After` 时优先采用该值。
- `400`/`403` 通常表示参数、权限或审核问题，修正输入前不应重复发送。
- 当前使用的 `gemini-3.1-flash-image-preview` 官方建议 timeout 为 360 秒。worker 自身、代理和网关的
  timeout 都不能小于这一长连接窗口。

## InsertAny3D 的保守策略

- 本地队列按“令牌指纹 + 模型名”隔离；密钥本身不写数据库或日志。
- 初始并发默认 4，可配置上限默认 24。只有连续成功和实际额度证据才逐步增加，不直接冲到公开值 30。
- 收到 429 后当前并发减半，并保存安全响应头（`Retry-After`、request ID、Rate Limit 字段）。
- `delivery_unknown` 暂停该任务等待人工决定；不自动重试，避免重复计费。
- 日常测试使用本地假 HTTP 服务，不用真实图片请求做并发压测。

这份文档只说明接口和调度规则，不代表当前令牌已经实测拥有 30 个并发。第一次正式批次应记录控制台额度
或响应头，再决定是否把配置从 4 调高到 12、24 或其他数值。
